# 智慧农联节点部署推荐系统 — 主要功能实现说明

本文说明本系统（基于 RuoYi 扩展的 `ruoyi-agricultural` 模块）**核心业务链路**、**关键源码路径**，并对 **部署算法** 与 **节点部署可视化（Canvas）** 做重点展开。

---

## 1. 模块与分层总览

| 层级 | 路径 | 说明 |
|------|------|------|
| 业务模块（领域、算法、Mapper、Service） | `ruoyi-agricultural/src/main/java/com/ruoyi/agricultural/` | 农业业务与算法实现 |
| MyBatis XML | `ruoyi-agricultural/src/main/resources/mapper/agricultural/*.xml` | SQL 映射 |

## 2. 各业务功能实现逻辑（简明）

### 2.1 农田管理

- **作用**：维护农田档案（名称、边界、面积、作物、`gridRows`/`gridCols` 等），为部署算法提供栅格规模。
- **后端**：`AgriFarmlandController` → `IAgriFarmlandService` / `AgriFarmlandServiceImpl` → `AgriFarmlandMapper` + `AgriFarmlandMapper.xml`。
- **实体**：`domain/AgriFarmland.java`。
- **前端**：`ruoyi-ui/src/views/agricultural/farmland/index.vue`，API：`ruoyi-ui/src/api/agricultural/farmland.js`。

### 2.2 环境监测数据

- **作用**：环境指标时序数据的查询与录入；支持按农田批量生成模拟数据（演示）。
- **后端**：`AgriEnvDataController` → `AgriEnvDataServiceImpl`（`generateSimulatedData` 在近 7 天时间窗内构造采样）→ `AgriEnvDataMapper` + XML。
- **实体**：`domain/AgriEnvData.java`。
- **前端**：`views/agricultural/envdata/index.vue`，API：`api/agricultural/envdata.js`。

### 2.3 节点部署方案（生成 + 列表 + 删除）

- **作用**：按农田与算法类型调用优化器，写入方案主表与节点明细表；列表查询、确认状态、删除（先删节点再删方案）。
- **后端入口**：`AgriDeploySchemeController.java`（`/agricultural/deploy/...`）。
- **核心事务**：`AgriDeploySchemeServiceImpl.generateScheme`（`@Transactional`）。
- **实体**：`AgriDeployScheme.java`、`AgriDeployNode.java`。
- **前端列表与生成**：`views/agricultural/deploy/index.vue`；API：`api/agricultural/deploy.js`。

### 2.4 用户评论

- **作用**：按 `targetType` + 内容发表评论；列表筛选、屏蔽/显示、删除。
- **后端**：`AgriCommentController` → `AgriCommentServiceImpl` → `AgriCommentMapper` + XML。
- **前端**：`views/agricultural/comment/index.vue`，API：`api/agricultural/comment.js`。

### 2.5 农业模块异常日志

- **作用**：记录农业相关接口异常，便于运维；列表、删除、清空。
- **AOP 拦截**：`ruoyi-agricultural/.../aspect/AgriErrorLogAspect.java`  
  - 切点：`com.ruoyi.web.controller.agricultural` 包下所有方法。  
  - 捕获异常后分类（如 `DATA_FORMAT`、`ALGORITHM_FAIL` 等），调用 `IAgriErrorLogService.recordError`（实现类中为 **`@Async` 异步** 写入，并截断过长字段）。
- **后端**：`AgriErrorLogController` → `AgriErrorLogServiceImpl` → `AgriErrorLogMapper` + XML。
- **前端**：`views/agricultural/errorlog/index.vue`。

### 2.6 算法配置（若菜单启用）

- **后端**：`AgriAlgorithmConfigController`、`AgriAlgorithmConfigMapper` + XML，实体 `AgriAlgorithmConfig.java`。  
- 当前**生成方案**流程中，超参主要在 `AgriDeploySchemeServiceImpl` 内写死/分支设置，配置表可作为扩展。

## 3. 部署算法 — 重点说明

算法代码集中在 **`ruoyi-agricultural/src/main/java/com/ruoyi/agricultural/algorithm/`**。

### 3.1 数据结构与参数

| 文件 | 职责 |
|------|------|
| `AlgorithmParam.java` | 栅格行列数、`sensorRadius`、`coverageTarget`、`clusterCount`、`maxIterations` 等超参 DTO。 |
| `NodeResult.java` | 算法输出的单节点：`nodeCode`、`nodeType`（sensor/sink）、`posX`/`posY`、`coverageRadius`、`energyLevel`、`clusterId`、`clusterHead`。 |

**坐标约定（与前后端一致）**：

- `posX` 对应**列方向**（c），`posY` 对应**行方向**（r）。
- 覆盖算法中传感器落在**整数格点**；sink 可落在半场中心（如 `cols/2.0`）。
- 前端 Canvas 绘图时：`canvasX = offsetX + posX * cellSize * scale`（与后端一致）。

### 3.2 覆盖优化 — `CoverageOptimizer.java`

**目标**：在 \(R \times C\) 栅格上，用半径为 `sensorRadius` 的**欧氏圆盘**覆盖尽量多格子，直到已覆盖比例 ≥ `coverageTarget`（如 0.9）。

**核心状态**：

- `boolean[][] covered`：每个格子是否已被某传感器圆盘覆盖。

**主循环（贪心）**：

1. 对每个格子 \((r,c)\) 调用 `calcGain`：若在该点放置传感器，圆盘内**当前仍为未覆盖**的格子数（只计增量）。
2. 选取 `gain` 最大的位置；若 `gain == 0` 或无法达到目标则停止。
3. `markCovered`：将该圆盘内所有格子标为已覆盖，并累加 `coveredCount`。
4. 生成 `NodeResult`：`nodeType=sensor`，`posX=c`，`posY=r`，编码 `S001`…。

**圆盘判定**：

- 对偏移 \((dr,dc)\)，若 \(dr^2 + dc^2 \le radius^2\) 且在栅格范围内，则属于该传感器覆盖范围。
- 扫描边界用 `ri = ceil(radius)` 缩小循环范围。

**Sink 节点**：

- 在农田中心附近追加 `SINK001`，`nodeType=sink`，`clusterHead=true`，半径取 `max(rows,cols)/2` 用于展示型大圆（与覆盖率统计分离）。

**覆盖率重算 — `calcCoverageRate`**：

- 仅对 `nodeType == "sensor"` 调用 `markCovered`，再统计 `true` 格子占比 ×100%。  
- **sink 不参与覆盖统计**，与优化阶段语义一致。

**复杂度直觉**：每一轮贪心需 \(O(R \cdot C \cdot r^2)\) 级别扫描（\(r\) 与半径相关）；轮数与目标覆盖率及增益分布有关。

### 3.3 聚类优化 — `ClusterOptimizer.java`

**目标**：在区域内布设多个传感器，用 **K-Means** 分簇，每簇选一个**距质心最近**的节点为簇头（`sink` + `clusterHead=true`），体现 LEACH 类「分簇 + 簇头」思想。

**步骤概要**：

1. **节点数估计**：`totalNodes = ceil( R*C / (π r?) * 1.5 )`，且 `totalNodes >= 3 * K`；其中 **`r` 在类内写死为 3.0**，与 `AlgorithmParam.sensorRadius` 解耦（注释中已说明为演示用）。
2. **随机布点**：`Random(42)`，坐标在 \([0, cols) \times [0, rows)\) 均匀随机。
3. **初始质心**：`initCenters` 在 \(\lceil\sqrt{K}\rceil \times \lceil\sqrt{K}\rceil\) 网格上均匀铺开 \(K\) 个中心。
4. **K-Means 迭代**（最多 `maxIterations`）：  
   - 分配：每个点归属欧氏距离最近的质心；若分配向量无变化则提前结束。  
   - 更新：`updateCenters` 对每簇求坐标均值；空簇回退到场中心；质心限制在 `[0, cols)` / `[0, rows)` 内。
5. **簇头**：对每个簇，找距离该簇质心**最近**的样本下标，记入 `headSet`；这些点编码 `CH01`…，类型 `sink`，其余为 `S001`… 类型 `sensor`。
6. **能量**：簇头 `energyLevel=100`；普通节点 `80 + random*20`，用于后续均衡指标。

**能量均衡得分 — `calcEnergyBalance`**：

- 对所有节点能量求均值 `avg`，再求能量标准差 `std`（总体标准差形式）。  
- 得分：`max(0, 100 - std)`，**std 越小越接近 100**。

### 3.4 服务层编排 — `AgriDeploySchemeServiceImpl.java`

**方法**：`generateScheme(farmlandId, algorithmType, createBy, userId)`  

1. 查询 `AgriFarmland`，读取 `gridRows`/`gridCols`（默认 20）。  
2. 构造 `AlgorithmParam`。  
3. 分支：  
   - **`coverage`**：`sensorRadius=3.0`，`coverageTarget=0.9` → `CoverageOptimizer.optimize` → `calcCoverageRate`；`energyBalance` 固定 **100**。  
   - **`cluster`**：`clusterCount=5`，`maxIterations=100` → `ClusterOptimizer.optimize`；**当前实现中** `coverageRate` 与 `energyBalance` **均取自** `calcEnergyBalance(nodeResults)`（列表展示字段约定，非栅格覆盖率）。  
4. 写入 `AgriDeployScheme`：`resultJson` 为 `NodeResult` 列表的 Fastjson2 序列化。  
5. `insertScheme` 后批量 `batchInsertNodes` 映射为 `AgriDeployNode`（`isClusterHead` 为 Y/N）。

**删除**：`deleteSchemeByIds` 先 `deleteNodesBySchemeId`，再删方案主表，保证一致性。

## 4. 节点部署可视化（图片/图形渲染）— 重点说明

可视化**不是静态图片文件**，而是浏览器端 **HTML5 Canvas 2D** 实时绘制矢量场景（可缩放、平移）。实现文件：

**`ruoyi-ui/src/views/agricultural/deploy/visualize.vue`**

### 4.1 进入方式与数据加载

- **路由**：`ruoyi-ui/src/router/index.js` 中隐藏路由  
  `path: '/agricultural/deploy-detail/visualize/:schemeId'`  
  权限：`agricultural:deploy:visualize`。  
- **列表页跳转**：`deploy/index.vue` 中 `handleVisualize` →  
  `this.$router.push({ path: '/agricultural/deploy-detail/visualize/' + schemeId })`。
- **数据**：  
  - `getScheme(schemeId)` → 方案概要（名称、算法类型、节点数、覆盖率、能耗均衡等）。  
  - `getSchemeNodes(schemeId)` → 节点列表（坐标、半径、类型、簇 ID 等）。  
  对应后端：`AgriDeploySchemeController` 的 `GET /agricultural/deploy/{id}` 与 `GET /agricultural/deploy/{id}/nodes`。

### 4.2 画布几何与视图变换

- **初始化**：`initCanvas` 根据 `canvasWrapper` 的 `clientWidth` 设置 `canvas` 宽高；高度至少 480，或与宽度成比例（`0.6 * width`）。
- **单元格尺寸**：`resetView` 在固定 `padding` 下，使 `cellSize = min(可用宽/cols, 可用高/rows)`，保证整块 \(cols \times rows\) 栅格适配画布。
- **视图状态**：  
  - `scale`：缩放系数（滚轮缩放，限制在 `[0.2, 10]`）。  
  - `offsetX` / `offsetY`：平移（空白处拖拽）。  
- **有效步长**：`cs = cellSize * scale`，所有网格与节点绘制基于 `cs`。

### 4.3 绘制顺序（`draw` 方法）

从底到顶依次为：

1. **背景农田区域**：浅绿色填充矩形 `cs * gridCols` × `cs * gridRows`。  
2. **网格线**（可开关 `showGrid`）：浅绿色细线绘制纵横线。  
3. **外边框**：加粗矩形描边。  
4. **覆盖范围**（可开关 `showCoverage`）：对每个节点以 \((offsetX + posX \cdot cs,\ offsetY + posY \cdot cs)\) 为圆心，`radius = coverageRadius * cs` 画半透明填充圆 + 虚线描边；sink 与普通 sensor 使用不同颜色透明度；若某簇被高亮（`highlightCluster`），颜色加深。  
5. **节点圆点**：sensor 蓝色、sink 红色；悬停时半径略大；在格距足够大或悬停时绘制 `nodeCode` 文本。

该顺序保证**圆盘在节点之下**，节点始终可见。

### 4.4 交互逻辑

| 操作 | 实现要点 |
|------|----------|
| **平移** | 在**非节点**区域 `mousedown` 记录拖拽起点，`mousemove` 中更新 `offsetX/offsetY`。 |
| **缩放** | `wheel`：以鼠标位置为锚点更新 `scale` 与偏移，避免「缩放飘移」。 |
| **节点点击** | `findNodeAt` 用欧氏距离判断是否在节点圆半径内；点击切换 `highlightCluster`（同簇高亮覆盖圆，再点取消）。 |
| **悬停提示** | `mousemove` 命中节点时显示绝对定位的 `canvas-tooltip`（编码、类型、坐标、半径、能量、簇 ID）。 |
| **左侧节点列表** | `focusNode` 将视图平移使该节点大致居中（基于当前 `scale`）。 |
| **快捷按钮** | 重置视图 / 显示或隐藏覆盖圆 / 显示或隐藏网格 → 布尔开关 + `draw()`。 |

### 4.5 与后端算法的一致性说明

- 可视化使用**与算法相同的格点坐标**：圆心 `posX`、`posY` 与 `cellSize` 线性映射，覆盖半径为 `coverageRadius` 个**格距单位**乘以 `cs`。  
- 页面中 `gridRows`/`gridCols` 当前在 `loadData` 里**写死为 20**；若农田实际栅格与库中不一致，仅影响底图格数展示，节点仍按存储坐标绘制——**若需严格一致**，可从方案或农田接口带回真实 `gridRows`/`gridCols` 并绑定。

## 6. 小结

- **算法**：覆盖 = 栅格贪心 + 圆盘覆盖；聚类 = 随机布点 + K-Means + 最近质心选簇头；结果统一为 `NodeResult` 列表再落库。  
- **可视化**：单页 Vue + Canvas 2D，按缩放与偏移将**离散格坐标**映射到像素，分层绘制网格、覆盖圆与节点，并支持拖拽、滚轮与簇高亮。  
- **扩展建议**：聚类分支若需在列表中展示**真实栅格覆盖率**，可在服务层对聚类结果额外调用 `CoverageOptimizer.calcCoverageRate`（仅 sensor）或独立统计逻辑，与 `energyBalance` 字段分离。
