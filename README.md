# 基于 WSN 的智慧农联节点部署推荐系统

**ruoyi-SARS**（Smart Agricultural Link Node Deployment Recommendation System）是一套面向智慧农业物联网的 **无线传感器网络（WSN）节点部署推荐系统**。系统在若依（RuoYi）前后端分离框架之上，把农田建模、部署算法计算、方案评估与节点可视化连成一条完整业务链，帮助使用者在给定农田范围内推荐传感器节点的放置位置，并对覆盖质量或分簇能量均衡给出量化结果。

---

## 系统能解决什么问题

农田环境监测需要布设传感器节点。节点放得太少会出现监测盲区，放得太密会浪费设备、增加能耗。本系统把农田抽象为栅格，用两种内置算法自动给出部署方案：

- **覆盖优化**：在给定感知半径下，尽量用较少节点覆盖更多栅格，逼近目标覆盖率。
- **分簇优化**：在区域内布点并分簇，为每簇选出簇头，便于观察簇结构与能量分布。

推荐结果包括每个节点的编码、类型、平面坐标、覆盖半径、能量水平、所属簇以及是否簇头，并可在画布上查看覆盖圆与节点分布。

## 技术架构

系统采用 **B/S + 前后端分离**：

| 层级 | 技术 | 作用 |
|------|------|------|
| 表现层 | Vue.js、Element UI、HTML5 Canvas | 业务页面、方案列表、节点部署可视化 |
| 控制层 | Spring MVC、Spring Security | 接收 HTTP 请求、权限校验、返回 JSON |
| 业务逻辑层 | Spring Boot、Java 算法组件 | 农田业务、覆盖/分簇算法、方案落库 |
| 数据访问层 | MyBatis、MySQL | 农田、方案、节点、环境数据、评论、日志等持久化 |

核心业务代码在 `ruoyi-agricultural` 模块；REST 入口在 `ruoyi-admin` 的 `controller/agricultural`；前端页面在 `ruoyi-ui/src/views/agricultural/`。

更细的算法与可视化说明见 [`docs/系统主要功能实现说明.md`](docs/系统主要功能实现说明.md)。

## 智慧农联节点部署（核心功能）

推荐流程可以概括为：**建农田 → 选算法生成方案 → 看评估指标 → 打开可视化 → 按需维护方案**。

### 1. 农田建模（部署的输入）

农田是算法的空间基础。每块农田除名称、面积、作物类型、边界数据外，还包含：

- **栅格行数 `gridRows`、栅格列数 `gridCols`**：把农田离散成网格，算法在网格上选点或布点。
- **归属用户**：普通用户主要维护自己的农田；生成方案时会读取该农田的栅格规模（未填写时按 20×20 处理）。

对应页面：农田管理。对应接口前缀：`/agricultural/farmland`。

### 2. 一键生成部署方案

在部署方案页面选择 **目标农田** 和 **算法类型**，调用生成接口：

- 路径：`POST /agricultural/deploy/generate`
- 参数：`farmlandId`（农田 ID）、`algorithmType`（`coverage` 覆盖优化 / `cluster` 分簇优化）

后端会在同一事务中完成：读取农田栅格 → 组装算法参数 → 运行对应优化器 → 写入 **方案主表** 与 **节点明细表**。方案名称按「农田名-算法简称-时间」自动生成。

生成后可查询：

- 方案列表与详情：`GET /agricultural/deploy/list`、`GET /agricultural/deploy/{schemeId}`
- 方案下全部节点：`GET /agricultural/deploy/{schemeId}/nodes`
- 修改方案状态/备注：`PUT /agricultural/deploy`
- 删除方案（先删节点再删主表）：`DELETE /agricultural/deploy/{schemeIds}`

### 3. 方案里有哪些结果

每条方案记录算法类型、节点数量，以及两个评估字段：

| 字段 | 覆盖优化（`coverage`） | 分簇优化（`cluster`） |
|------|------------------------|------------------------|
| 覆盖率 `coverageRate` | 按传感器圆盘覆盖的栅格比例（百分比） | 当前实现写入的是能量均衡得分（与列表展示约定一致） |
| 能量均衡 `energyBalance` | 固定为 100（占位，本算法不以能耗为优化目标） | 按节点能量标准差计算：`max(0, 100 - 标准差)`，越均衡越接近 100 |

每个节点包含：节点编码、类型（`sensor` / `sink`）、`posX`/`posY`（列/行方向坐标）、覆盖半径、能量水平、簇编号、是否簇头（Y/N）。算法原始节点列表还会以 JSON 保存在方案的 `resultJson` 中。

**坐标约定**：`posX` 为列方向，`posY` 为行方向，与前端 Canvas 绘制一致。

### 4. 覆盖优化算法（Coverage）

实现类：`CoverageOptimizer`。

思路是 **栅格贪心 + 欧氏圆盘覆盖**：

1. 用农田行、列构造覆盖标记矩阵。
2. 每一轮扫描所有格点，计算在该点放一个传感器能 **新覆盖** 多少尚未覆盖的格子。
3. 选增益最大的格点落点，编码为 `S001`、`S002`…，类型为 `sensor`。
4. 当覆盖比例达到目标（当前生成流程中目标覆盖率为 **0.90**，感知半径 **3.0** 格）或再也没有正增益时停止。
5. 在农田几何中心追加汇聚节点 `SINK001`（类型 `sink`，展示用较大半径）。**覆盖率统计只计入 sensor，sink 不参与。**

适合关心「这块田被监测到了多少」的场景。

### 5. 分簇优化算法（Cluster）

实现类：`ClusterOptimizer`。采用 **随机布点 + K-Means 分簇 + 近质心选簇头**（LEACH 类分簇思想的演示实现）：

1. 按栅格面积与固定半径估算节点数，并保证不少于 `3 × 簇数`。
2. 在 `[0, 列数) × [0, 行数)` 内随机布点（随机种子固定，结果可复现）。
3. 在场上均匀铺开 K 个初始质心，迭代分配最近点、更新质心，直到稳定或达到最大迭代次数。
4. 每个簇中离质心最近的点作为簇头：编码 `CH01`…，类型 `sink`，能量为 100；其余为普通传感器 `S001`…，能量在 80～100 之间。

当前生成流程中簇数 **5**、最大迭代 **100**。适合观察簇结构、簇头位置和能量均衡得分。

### 6. 节点部署可视化

可视化不是静态图片，而是浏览器 **Canvas 2D** 实时绘制。从方案列表进入：

`/agricultural/deploy-detail/visualize/{schemeId}`

页面会拉取方案摘要和节点列表，按图层绘制：

1. 浅绿色农田区域与网格（可开关）
2. 各节点覆盖圆（半透明，sink 与 sensor 颜色不同，可开关）
3. 节点圆点：sensor 蓝色、sink 红色；可显示编码

支持滚轮缩放、拖拽平移、悬停查看节点属性、点击节点按簇高亮、左侧列表定位某个节点。覆盖圆半径按「覆盖半径 × 单元格像素」映射，与后端格点坐标一致。

### 7. 算法配置查询

接口 `GET /agricultural/algorithm/list` 可返回已启用的算法配置（类型、名称、参数 JSON、说明）。**当前真正生成方案时，覆盖半径、目标覆盖率、簇数、迭代次数等超参在服务层按算法类型写入**，配置表主要用于展示与后续扩展，不会在本次生成中被动态读取覆盖。

## 配套业务功能

这些模块服务部署主链路，不是独立的「环境监测硬件系统」。

### 环境数据

按农田记录气温、空气湿度、光照、土壤湿度、风速及采样时间；支持手工录入、按农田批量生成模拟数据（单次 1～500 条，时间落在近若干天内）以及列表查询、删除。用于演示「部署后可对照查看环境记录」，**不是实时传感器采集**。

### 评论交流

用户可对指定对象类型（如系统、算法、可视化等）发表内容、评分、图片地址，可匿名。管理员可按条件查询、改状态（显示/屏蔽）、删除。用于收集对部署方案或系统使用的反馈。

### 农业异常日志

对 `agricultural` 包下控制器做 AOP 拦截：接口抛错时分类（如数据格式、算法失败等），异步写入错误类型、摘要、堆栈、请求 URL 与参数、操作人。后台可查询、删除、清空，便于排查生成方案失败等问题。

## 系统管理（若依内置）

本系统基于 RuoYi 3.8.7，仍保留账号体系与运维能力，与部署业务配合使用：

- 用户、角色、菜单、部门、岗位、字典、参数、通知公告
- 登录/操作日志、在线用户、定时任务、代码生成、接口文档
- 服务监控、缓存监控、连接池监视等

权限按菜单标识控制，例如农田 `agricultural:farmland:*`、部署 `agricultural:deploy:*`（含可视化 `agricultural:deploy:visualize`）。普通角色与管理员角色的菜单范围可通过 SQL 脚本配置（见 `sql/agricultural_auth_and_demo_data.sql`）。

## 推荐使用步骤

1. 使用管理员或已授权账号登录。
2. 在 **农田管理** 中新增农田，填写合理的栅格行、列（影响算法规模与耗时）。
3. 打开 **部署方案**，选择该农田，算法选「覆盖优化」或「分簇优化」，生成方案。
4. 在列表中查看节点数、覆盖率、能量均衡；进入可视化核对节点与覆盖圆。
5. 需要对比时，对同一农田再生成另一种算法的方案，对照指标与图形。
6. 可选：为该农田生成环境模拟数据；在评论中记录使用感受；异常时到错误日志查看堆栈。

## 环境与启动

- 后端：JDK 8、Maven、MySQL（库名以实际配置为准，演示脚本使用 `ry-sars`）
- 前端：Node.js；若 Node 高于 16，启动前需设置 OpenSSL 兼容参数

前端：

```text
1. 换源：npm config set registry https://registry.npmmirror.com
2. 进入 ruoyi-ui，执行 npm install
3. 需要图表时：npm install echarts --save
```

## 使用与扩展时注意

- 覆盖优化每一轮会扫描整张栅格，农田网格过大时生成会变慢。
- 分簇分支列表中的「覆盖率」字段当前与能量均衡同源，不是栅格覆盖百分比；若要同时展示真实覆盖率，需在服务层对 sensor 节点另行统计。
- 可视化页网格默认按 20×20 绘制底图；节点仍按库中坐标绘制。农田栅格与 20 不一致时，底图格数可能与建模不完全一致。
- 环境数据以库表维护和模拟生成为主，未对接真实传感器协议。
